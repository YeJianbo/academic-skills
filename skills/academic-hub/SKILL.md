# Academic Hub

按用户当前要得到的产物确定负责人，不把全部学术技能依次加载。对整篇或端到端任务，可给各项交付分配负责人并在已有授权内持续完成。

## 直接路由

| 当前任务 | 入口 |
|---|---|
| 新方向、跨论文调研或研究路线协调 | `survey`；明确检索直接 `cs-literature-search` |
| 整篇写作组织、跨章节交付 | `writing`；局部起草或改写直达对应技能 |
| 审查范围不清或需要协调专项检查 | `review`；完整审稿直达 `cs-paper-reviewer` |
| 实验全流程和多轮执行协调 | `experiment`；明确运行直接 `run-experiment` |
| 学术文件、引用及工具任务分流 | `tools`；已知工具任务直达专用技能 |

每项产物只有一个当前负责人；只在存在具体证据缺口或用户组合请求时增加相邻能力。技能交接不等于子代理调用，也不是额外审批。

## 按需资料

- 入口冲突、技能维护或不知道谁负责：读 [责任与触发边界](references/routing.md)。
- 跨阶段交接、版本比较或文件整理：读 [增量学术工作流](references/incremental-academic-workflows.md)。
- 首次组织论文主线或结构性修改：读 `references/publication-story-principles.md`。

局部修改复用现有材料，探索性请求保留可检验候选与不确定性。证据约束、用户模板和范围始终有效；短任务不新建项目台账。
