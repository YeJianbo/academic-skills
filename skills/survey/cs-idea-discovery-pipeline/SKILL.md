# CS Idea Discovery Pipeline

## 按请求确定范围

从本次请求、已有文件和上下文明确问题、证据范围、所需验证与交付物；不沿用无关旧任务的主题或投稿目标。未指定会议时先研究问题，不要求用户先选 venue。

| 请求 | 执行范围 |
|---|---|
| 查几篇论文或下载已指定论文 | 使用 cs-literature-search 或 scansci-pdf；不启动完整选题流程。 |
| 评估单个 idea | 核对相近工作、假设、失败机理和反例，给出证据与判断；无需凑多个候选或完整实验。 |
| 初步选题或论文大纲 | 基于已有材料给候选、主张与证据对应关系、未解决项及下一步验证；标为初步，不声称已证明可行或有新意。 |
| 从文献到经验证的研究方向 | 执行下述完整流程，在用户给定的时间、资源和任务范围内迭代。 |

## 证据边界

- 不编造引用、数据、读过的论文或证明结果。标题、摘要、下载状态、关键词分组、模型意见分别记录，不能冒充全文证据。
- 强新颖性或结构性空白判断需有相近工作检索和相关全文依据。只掌握摘要时明确限于摘要；不能因为有 PDF 就宣称读过，也不能因为没有 PDF 文件就把实际读过的官方 HTML 全文降成元数据。
- 证据卡作为回链索引，跨论文结论仍需核对模型、假设、方法、定理或实验、失败条件和适用范围。缺少相关证明、攻击或附录细节时回原文补读。
- 不用理论猜测替代证明，不把枚举或 CPU/toy 功能验证写成一般安全性或正式性能结果。原型成功也不等于投稿证据已经完整。
- 查可能否定候选的工作和反例，不能只收集支持材料。验证失败如实记录，不能靠更弱对照或更换度量掩盖失败。
- 用户要求从头开始或不参考旧材料时，遵守该范围；较长研究在运行记录中写清禁用旧目录。

## 完整研究流程

以下为端到端研究的工作顺序，复用已有有效成果，不要求每次重新执行全部步骤。

1. **问题与检索范围**：记录主题、关键词、最近三年或用户指定年份、排除项、资源和可用验证方式。投稿 venue 是适配信息，除非用户明确限制，否则不缩成单一会议检索。
2. **检索与筛选**：优先官方 proceedings、DBLP、领域顶会/顶刊、强相邻领域及高质量预印本。按相关性分批检索和阅读，不用固定篇数作为启动验证的前提。对探索性候选先筛标题/摘要，再下载高相关全文；用户已指定的论文直接获取。
3. **阅读与比较**：结合原文和已有 distilled cards，记录问题、模型/威胁、关键假设、方法、主张、证据锚点、失败条件和可验证线索。多篇比较时维护 evidence matrix；下载数量和自动分类不算阅读证据。
4. **假设与替代解释**：从共享假设或具体失败场景提出可证伪问题，解释为何现有方法失效。开放选题比较有实质区别的候选；用户指定单个 idea 时直接评估它，不凑数。存在具体证据缺口时再定向扩展，不自动追加大批相邻论文。
5. **相近工作与审查**：检查最可能撞车的工作、反例、定义和比较条件；区分已确认问题、合理风险和缺失证据。当前线程完成必要检查，独立代理仅按下节条件使用。
6. **最小验证**：根据主张选择证明检查、反例构造、有限枚举、原型、复现或实验。先验证假设的关键环节，再决定是否开展方法比较或主实验。理论贡献不强制转换为训练或性能提升实验。
7. **判断与交付**：说明支持了什么、证据边界和未解决项。假设不成立则记录原因，在剩余范围内修正或换候选；不把负结果包装成成功。给出用户所需的方向、大纲或后续计划。

## 检索和材料管理

检索按 cs-literature-search 的来源选择执行；OpenAlex 仅在用户指定或现有路径不足且确有需要时采用。API 限流、超时或配额耗尽时记录原因并转官方页面、作者主页等来源，不反复空转。重复查询复用缓存。

优先直接获取 OA、arXiv、官方会议或作者全文；批量和困难下载可用 scansci-pdf。只有实际需要订阅访问时才进入 institutional-access-resolver，已指定论文不必再走探索性筛选。去重并记录标题、作者、年份、DOI/arXiv、全文来源与真实阅读状态。

较长或跨轮研究可使用现有辅助脚本，命令参数按本次任务填写：

```powershell
python scripts/init_research_run.py --out-dir "<run-dir>" --topic "<topic>" --year-window "<years>" --target-venue "unspecified" --search-scope "<scope>"
python scripts/evidence_count_ledger.py --screening metadata/screening_matrix.csv --download-status metadata/download_status.csv --read-status metadata/read_status.csv --evidence-matrix notes/matrices/core_evidence_matrix.md --out metadata/evidence_counts.md
```

用户要求 fresh start 时给初始化命令添加 `--fresh-start --forbidden-old-dir "<old-run-dir>"`。维护已有运行记录，文件名和计数脚本不是提出初步假设或开展小验证的前提。

计数需区分 metadata_found、title screened、abstract reviewed、downloaded、fulltext_read 和 evidence matrix rows。`human_abstract_yes` 表示主线程或人工读过摘要后的相关性判断，不表示必须再找用户审批。自动关键词评分不能直接变成阅读结论。

## 代理协作

默认由当前线程完成。只有任务有独立、明确的子问题，且用户或适用上层规则已授权代理协作时，才按职责选用当前可用代理，例如相近工作检查、技术可行性或反例审查；不固定模型名称或人数。代理调用与 quorum 不是输出候选、大纲或结论的前提。

需要 AGY 且已有授权时，使用 `agy` skill 中的模型选择与本地后台 helper；不以前台等待替代当前线程的工作。读取实际返回内容后再引用，失败、超时或缺失部分如实保留；代理判断不替代原文、证明或实验。

## 验证与停止

按研究主张选择验证：理论/密码学检查定义、证明、反例和必要的枚举；系统研究做 microbenchmark 或 trace replay；学习方法按需做配对 seed、有效对照和攻击评估；HCI 按实际授权做原型或研究设计。先检查实际需要的依赖；不假定 CUDA 已配置，也不为纯理论任务探测 GPU。

完整研究中，成功条件是证据支持限定主张且主要反例已处理；失败条件包括反例成立、关键假设不可满足或合理范围内无信号。环境失败与科学负结果分开报告，CPU 降级结果标明条件。用户所需交付完成，或候选在给定预算内均被否定时，报告实际结论，不为了得到一个正结果无限扩展。

初步大纲无需先证明整个方法成立；将待证定理、待测实验和未核验新颖性明确列为待完成项。只有证据足够时才称为“经验证的方向”。

## 交付

按用户范围提供候选或结论、依据与来源、主要假设及失败条件、已做验证和下一步。初步请求可直接在聊天交付；长研究保存检索/下载失败记录、阅读矩阵、代码或证明、运行结果和论文大纲，并链接实际文件。未调用的代理、未运行的实验不生成假报告；不要求固定 19 项输出。
