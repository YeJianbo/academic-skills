# Writing

按用户要求完成正文或文件。完整稿件可以内部逐节处理，不在初稿或技能交接处默认停下。局部编辑保留现有结构，不重新规划整篇论文。

| 交付 | 负责技能 |
|---|---|
| 整篇蓝图、贡献边界、章节职责或主线重构 | `paper-architecture-planner` |
| 从材料起草摘要、章节或整篇正文 | `section-drafter` |
| 润色、翻译、压缩已有文本 | `section-writing-polish` |
| 将文献证据组织成 Related Work | `related-work-synthesizer` |
| 安全/隐私定义、定理和证明起草 | `security-proof-builder` |
| 显式去 AI 味或去防御性表达 | `academic-paper-de-vibe` |

负责人按需吸收去防御性表达原则，不为每次写作启动另一轮完整审查。直接陈述问题、机制与证据；删除空泛自辩和贡献自谦，保留真实假设、负面结果及必要披露。模板、公式、引用和术语不因润色改变含义。

默认交付最终文本和必要未决问题。内部计划、自检、版本状态不自动写入正文或最终回复。沿用现有规范文件路径，原始证据与必要历史保留。

## 按需资料

- 首次规划或结构性修改主线：`../academic-hub/references/publication-story-principles.md`。
- 责任边界或风格协作不清：`references/local-skill-integration.md`。
- 版本与文件交接：`../academic-hub/references/incremental-academic-workflows.md`。
- 用户明确指定 Nature/Science/Cell 等表达风格：参考 `scipilot-writing-skill`。
